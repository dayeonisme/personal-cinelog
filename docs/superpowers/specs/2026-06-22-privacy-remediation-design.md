# 개인정보 노출 정리 설계

## 목표

공개 GitHub 저장소와 도달 가능한 Git 이력에서 확인된 개인정보 및 운영 식별자를 제거하고, 같은 값이 이후 커밋에 다시 들어오는 것을 방지한다.

## 범위

- 현재 추적 파일에서 실명, 로컬 사용자명·절대 경로, VM 이름과 존을 제거한다.
- 커밋 훅은 공개 소스에 개인 값을 포함하지 않고 일반 패턴과 로컬 Git 설정의 개인 패턴을 함께 검사한다.
- 테스트는 실제 개인정보가 아닌 가짜 로컬 패턴을 사용해 훅의 동작을 검증한다.
- `master` 전체 이력의 파일 내용과 author/committer 메타데이터를 재작성한다.

## 현재 노출 항목

- 커밋 author/committer 메타데이터의 실명, Gmail 주소, 로컬 Mac 호스트명 포함 이메일
- `scripts/pre-commit`의 실명·사용자명 검사값
- `tools/cleanup_db_backups.sh`의 로컬 절대 경로
- `deploy/README.md`의 VM 이름과 GCP 존

API 키, 비밀번호, 세션·쿠키 파일, 데이터베이스, 업로드 파일은 이번 점검에서 발견되지 않았다.

## 설계

### 현재 파일 정리

- DB 백업 정리 스크립트는 스크립트 자신의 위치에서 저장소 루트를 계산한다.
- 배포 문서는 실제 VM 이름과 존 대신 `<VM_NAME>`, `<ZONE>` 자리표시자를 사용한다.
- 저장소 훅에서 실명과 사용자명 리터럴을 제거한다.

### 로컬 개인정보 검사

저장소 훅은 일반적인 절대 경로, 비밀값, 세션·DB 파일 규칙을 계속 검사한다. 사용자 고유 문자열은 추적되지 않는 로컬 Git 설정에서만 읽는다.

```text
git config --local --add cinelog.privacyPattern '<pattern>'
```

훅은 설정된 패턴마다 staged diff의 추가 행을 검사하고, 매치 시 커밋을 중단한다. 설정이 없으면 일반 규칙만 수행한다. `--no-verify`는 Git의 의도된 우회 옵션이므로 기술적으로 완전히 차단할 수 없으며, 사용하지 않는 운영 규칙을 적용한다.

### 이력 재작성

`git filter-repo`로 `master` 전체 이력에서 노출 문자열을 중립적인 값으로 치환한다. 동시에 기존 개인정보 author/committer 이름과 이메일을 GitHub noreply ID로 교체한다. 재작성 후 원격 `master`를 강제 푸시한다.

재작성 후 기존 SHA는 모두 바뀐다. 기존 클론은 재복제 또는 원격 기준 강제 동기화가 필요하며, 이미 외부에 복제된 이력·캐시는 통제할 수 없다.

## 검증

1. 새 훅 테스트가 수정 전에는 실패하고 수정 후에는 통과하는지 확인한다.
2. `python3 -m pytest -q`, `node --check static/js/app.js`, `git diff --check`를 실행한다.
3. 재작성된 전체 이력에서 실명, 기존 이메일, 호스트명, 절대 경로, VM 이름·존 및 일반 비밀값 패턴이 없는지 검사한다.
4. 원격을 다시 fetch하고, 공개 `origin/master`가 재작성된 `master`와 일치하는지 확인한다.
